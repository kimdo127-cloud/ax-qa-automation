# QA 자동화 (구글 시트 + Gemini + GitHub Actions)

피그마 디자인과 기획 메모를 기준으로 IA → 테스트 시나리오 → 테스트케이스를 만들고, 실제 브라우저로 N차 QA를 돌려 결함을 기록·재확인합니다.

## 구성
| 폴더 | 내용 |
| --- | --- |
| `apps-script/` | 구글 시트에 붙는 Apps Script (메뉴, 입력 창, Gemini 호출, 결과 반영, 웹앱) |
| `runner/` | Playwright 실행기 (시트에서 테스트케이스를 받아 실행, 결과·실패 화면 전송) |
| `.github/workflows/qa.yml` | 시트의 'QA 실행' 버튼이 호출하는 GitHub Actions |
| `design/` | 피그마 디자인과 같은 정상 화면 (예제) |
| `example-site/` | 테스트 대상 사이트 (예제, 오류를 심어 둠) |
| `docs/과제문서.md` | 현재 업무 분석 · 개선 설계 |

## 실행 방법
1. 구글 시트 메뉴 **QA 자동화 → 설정**: Gemini API 키, GitHub 토큰(이 저장소 Actions 읽기·쓰기), 피그마 토큰(파일 읽기), 웹앱 주소 입력 (최초 1회)
2. **QA 실행 창 열기** → 피그마 링크 · 테스트 대상 URL · 기획 메모 입력 → **IA · 시나리오 · 테스트케이스 만들기** (약 1~2분)
3. **QA 실행 (다음 차수)** → 1~3분 뒤 테스트케이스(차수별 결과) · 결함(스크린샷) · IA(최근 결과) · 요약 시트 확인
4. 결함 시트 **개발자 표기**에 `수정완료` → 다시 **QA 실행** → 통과면 `재확인 통과·종료`, 실패면 `재오픈`
5. 시연을 처음부터 다시 하려면 **QA 기록 초기화 (시연용)**

## 새로 설치할 때
- `apps-script/`를 `clasp push`로 시트에 올리고 `clasp deploy`로 웹앱 배포 (접근: 모든 사용자)
- 키는 시트의 스크립트 속성에만 저장됩니다. 코드·저장소에 넣지 않습니다.
